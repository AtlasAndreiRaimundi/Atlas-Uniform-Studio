# Procedimento para releases e preservação

**Observação:** Git registra versões de arquivos efetivamente enviados. Não sincroniza automaticamente o site publicado nem cria presunção de titularidade.

## Procedimento
1. Revisar mudanças, segredos, dados pessoais e licenças de ativos.
2. Testar as funcionalidades e registrar os resultados.
3. Atualizar CHANGELOG.md e identificar o commit de origem.
4. Criar uma tag sem reutilizar nomes anteriores (por exemplo v0.1.0-docs, v0.2.0-beta).
5. Exportar o arquivo ZIP completo correspondente ao código efetivo dessa versão. Preservar os bytes originais do ZIP.
6. Calcular SHA-256 do ZIP final e registrar no inventário de evidências.
7. Guardar o ZIP em armazenamento privado com cópia de segurança independente do GitHub.
8. Registrar evidências cronológicas externas verificáveis, evitando retroagir datas.

## Cuidados jurídicos
Revisar contrato de trabalho e eventuais ativos de terceiros antes de distribuir ou comercializar. Este procedimento é organizacional e não substitui parecer jurídico nem registro do software perante o INPI.
